# Архитектура game_v0.2

Go HTTP-сервер раздаёт встроенный интерфейс HTML/CSS/JS. Frontend только отображает данные и отправляет намерения. PostgreSQL — источник истины для аккаунтов, сессий, шаблонов, комнат, выбранных решений и результатов.

## Модули

- `model.go`: фиксированная модель 10 индикаторов, валидация, лаги, синергии, штрафы, предельные вклады, поиск допустимых замен одного решения.
- `game.go`: независимые игроки, лобби, готовность, замороженные условия, локальная передача хода, RuleBot, WebSocket.
- `server.go`, `features.go`: сессии, RBAC, профили, шаблоны, история, рейтинг.
- `database.go`, `store.go`: транзакции PostgreSQL и сериализованные агрегаты.
- `ai.go`, `city_ai.go`: отдельные сценарии генерации города и анализа завершённой игры. Бот не вызывает LLM и не читает решения соперников.
- `report.go`: настоящий PDF с кириллическим шрифтом и DOCX Open XML; данные берутся из сохранённого результата.

## Хранение

Таблицы `users`, `sessions`, `cities`, `config`, `rooms`, `results` имеют первичный ключ `key` и JSONB `data`. У результатов есть индексы по игроку, комнате и статусу. Комната содержит участников, готовность и черновики решений; результат содержит неизменный снимок правил/данных, решения, расчёт, AI-анализ и модель. Такой агрегат сохраняет воспроизводимость старых отчётов при редактировании шаблонов. Это упрощённая схема для MVP, а не полная нормализация всех сущностей master prompt.

Записи проходят через транзакции с advisory lock. Это защищает одновременное присоединение и двойную сдачу, но ограничивает масштабирование записей. Для больших нагрузок нужны блокировки отдельных комнат и нормализованные участники/решения.

## Состояния

Комната: `lobby → playing → scored → complete`. `complete` — только после всех AI-анализов.

Результат: `waiting_players → analyzing → complete`, при ошибке — `analysis_failed`. Перезапуск переводит незавершённые запросы AI в ошибку с возможностью повторить. Повторный экспорт не обращается к AI.

Место определяется после сдачи всех сценариев; равные Score делят место. Одиночная игра не даёт победу в глобальном рейтинге, локальные гости и боты не входят в него. В рейтинге учитываются только результаты с завершённым AI-анализом.

## Ограничения текущего MVP

- Исходные два PDF не приложены; seed перенесён из `main`, контрольные значения совпадают с master prompt.
- WebSocket отправляет изменения комнаты, проверяя БД раз в секунду. Внешний брокер событий пока не используется.
- Списки истории/комнат/статистики пока без серверной пагинации; для большого количества игр необходимо её добавить.
- DOCX сформирован как пакет Open XML; автоматические тесты проверяют ZIP/XML. Ручной просмотр в Microsoft Word ещё требуется.
- Проверка структурированного ответа AI гарантирует разделы, но не истинность каждого предложения LLM; численные таблицы всегда принадлежат scoring engine.
- Для production нужны HTTPS-прокси, резервное копирование PostgreSQL, мониторинг, лимиты регистраций/комнат и устойчивый внешний worker AI.
