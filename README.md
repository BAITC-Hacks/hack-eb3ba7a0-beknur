# Аким на 5 часов

Интерактивный симулятор с локальным сервером AI-анализа для Astana Innovations. Данные районов и стоимость мероприятий синтетические; модель не является прогнозом или официальной оценкой города.

## Запуск

Нужен Node.js 22 или новее. Дополнительных зависимостей нет, `npm install` не требуется.
Из папки с `package.json`, `server.cjs` и `.env` запустите:

```powershell
node server.cjs
```

Откройте http://127.0.0.1:3000. Эквивалентная команда — `npm start`; если PowerShell блокирует `npm.ps1`, используйте `npm.cmd start`.
Сначала заполните блок **«Настройка симуляции»** и нажмите **«Применить настройки»**. Затем выберите пять допустимых решений и нажмите **«Получить AI-анализ»**. Кнопка отправляет один запрос; при изменении сценария старый анализ сбрасывается. Запросы к OpenAI оплачиваются по тарифу вашего API-проекта.

Без сервера можно открыть `dist/index.html`: расчёт и базовое объяснение работают офлайн, AI-анализ недоступен.

## Настройка OpenAI API

Существующий `.env` с ключом перезаписывать не нужно. Если файла ещё нет, скопируйте `.env.example` в `.env` рядом с `server.cjs` и задайте:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-6-luna
PORT=3000
```

`OPENAI_MODEL` должен содержать идентификатор модели, доступной вашему API-проекту. После изменения `.env` перезапустите сервер (Ctrl+C, затем `node server.cjs`). Наличие ключа не гарантирует доступ к модели или достаточную квоту.

Сервер загружает `.env` относительно своего файла. Уже заданные переменные окружения имеют приоритет. Ключ не включается в HTML, ответы или журналы; `.env` исключён из Git и недоступен по HTTP.

`POST /api/analyze` принимает `{ "config": { "budget": ..., "districts": [...], "measures": [...], "demoRules": false }, "decisions": [...] }` (ровно пять решений). Настройки обязательны: сервер проверяет числовые диапазоны, названия, каталог и сценарий, самостоятельно рассчитывает показатели и вызывает [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text). Передаются синтетические данные: решения, стоимость, Score, дельты, отдельные эффекты и синергии. Используется `store: false`. Клиентские Score и произвольные инструкции не используются.

LLM объясняет готовые результаты и предлагает качественные рекомендации. Числа в интерфейсе берутся только из модели; текст LLM может содержать ошибки и не меняет расчёт. При ошибке сети, ключа, модели, квоты или тайм-ауте интерфейс показывает причину; базовое объяснение сохраняется.

Сервер слушает только `127.0.0.1`, отклоняет запросы с других сайтов и разрешает один одновременный AI-запрос с интервалом минимум 3 секунды. Это локальный режим: публичное размещение потребует авторизации пользователей и лимитов на пользователя.

## Проверка

```powershell
node --test tests/*.test.cjs
```

Также доступны `npm test` / `npm.cmd test`. Тесты не читают `.env` и не вызывают платный API: проверяют контрольные баллы, валидацию, серверный расчёт, закрытый доступ к файлам конфигурации, ошибки провайдера, тайм-ауты и сброс устаревшего AI-ответа.

## Обязательная настройка симуляции

При открытии страница не подставляет исходные данные автоматически. Она показывает сообщение «Введите бюджет, добавьте районы и не менее пяти мероприятий». До применения корректных настроек выбор решений, подбор и AI-анализ недоступны.

1. Введите положительный **бюджет** (до 1 млрд условных единиц).
2. Добавьте **1–10 районов**: уникальное название, население целым числом и все десять исходных показателей от 0 до 100. Доли районов вычисляются из населения автоматически.
3. Добавьте **5–20 мероприятий**: название, направление, положительную стоимость, районный/городской охват и лаг 0–8 кварталов. В раскрывающемся блоке эффектов задайте изменения показателей от −100 до +100; ноль означает отсутствие влияния.
4. Нажмите **«Применить настройки»**. Ошибки и незаполненные поля перечисляются под формой. После применения появляются исходные таблицы, каталог и выбор пяти решений.

В списке **«Город или ручной ввод»** доступны Астана, Алматы, Шымкент, Караганда, Актобе, Атырау, Павлодар, Усть-Каменогорск, Тараз и Семей. Выберите город и нажмите **«Загрузить выбранный город»**: форма заполнится учебным набором, после чего его можно отредактировать и применить. Сам выбор пункта не заменяет введённые данные.

Названия территорий сверены с официальными источниками, ссылки доступны рядом с выбором города. Все бюджеты, население, показатели и эффекты остаются синтетическими. Астана сохраняет исходный учебный пример без изменений.

- Алматы: все 8 административных районов — Алатауский, Алмалинский, Ауэзовский (Әуезов), Бостандыкский, Жетысуский, Медеуский, Наурызбайский, Турксибский. [Акимат Алматы](https://www.gov.kz/memleket/entities/almaty/activities/27965).
- Шымкент: Абай, Әл-Фараби, Еңбекші, Қаратау, Тұран. [ДГД Шымкента](https://shymkent.kgd.gov.kz/ru/content/spisok-nalogoplatelshchikov-podlezhashchih-prinuditelnoy-likvidacii-soglasno-normam-stati--0).
- Караганда: район имени Казыбек би и район Әлихан Бөкейхан. [Акимат Казыбек би](https://www.gov.kz/memleket/entities/karaganda-rayon-im-kazybek-bi?lang=kk), [акимат Әлихан Бөкейхан](https://www.gov.kz/memleket/entities/karaganda-alikhan-bokeikhan).
- Актобе: Астана и Алматы. [Әділет](https://adilet.zan.kz/rus/docs/G25CA00383M).
- Тараз: Әулиеата и Жібек жолы. [Акимат Тараза](https://www.gov.kz/memleket/entities/zhambyl-taraz/press/news/details/1148031).
- Атырау: Нурсая, Жилгородок, Жумыскер, Авангард. Выборка микрорайонов из [перечня городских маршрутов](https://law.gov.kz/api/documents/161791/rus/13.12.2021/download/pdf).
- Павлодар: Достык, Жастар, Усольский, Восточный. Выборка микрорайонов из [сообщения акимата](https://www.gov.kz/memleket/entities/pavlodar/press/news/details/759303?lang=ru).
- Усть-Каменогорск: КШТ, Аблакетка, Согра, Защита, Куленова. Выборка микрорайонов из [сообщения МЧС](https://www.gov.kz/memleket/entities/emer/press/news/details/492661?lang=ru).
- Семей: Карагайлы, Юность, Жоламан, Восточный, Степной. Выборка жилых районов/микрорайонов из [схемы генерального плана](https://www.gov.kz/uploads/2024/3/19/f791cb6b3ed23b6afdaebf7d4ed875ce_original.25794169.pdf).

Для последних четырёх городов наборы не являются полным перечнем территорий и не выдаются за административное деление. Все наборы содержат бюджет 100 и 14 мер. Имя выбранного города передаётся в AI-анализ вместе с расчётом.

Режим **«Ввести вручную — свой город»** оставляет возможность самостоятельного ввода. Кнопка **«Начать новый ручной набор»** очищает форму и сбрасывает расчёт. Для готового набора также требуется нажать **«Применить настройки»**. Несовместимости и синергии примера включаются отдельным флажком. Для собственного каталога этот флажок по умолчанию выключен: случайное совпадение ID с M1–M14 не добавляет скрытые правила.

Изменение любого поля настройки отменяет незавершённый подбор/AI-запрос, сбрасывает выбранные решения и скрывает симуляцию до повторного применения. Настройки хранятся в памяти текущей страницы; при её перезагрузке ввод начинается заново.

После применения видны все показатели по пяти направлениям, доли населения и каталог с ценами. Критические значения ниже 40 отмечены знаком `!`.

## Сценарий

Выберите ровно пять разных мероприятий из своего каталога. Для районных мер укажите один из заданных районов. Нельзя превышать настроенный бюджет или выбирать более двух мер одного направления. При включённых правилах примера запрещены M1+M3 в любых районах, M4+M7 и M5+M13 в одном районе. Невалидный набор не получает балла; интерфейс показывает причину.

## Автоматический подбор

Нажмите **«Подобрать лучший план»**. Алгоритм перебирает все сочетания пяти разных мер и назначения районов, отбрасывая нарушения бюджета, направлений и несовместимостей. Каждый допустимый план проверяется общим валидатором и оценивается исходной функцией `compute`, включая лаги, синергии, ограничение 0–100 и критические показатели. Максимум сравнивается до экранного округления; при равных баллах (с допуском 1e-10 для арифметики) выбирается более дешёвый план, затем первый в порядке каталога и районов.

Для встроенного примера проверяется **694 395 допустимых планов**. Максимальный Score **57.236735**, стоимость **98**: M2/город, M3/Нура, M8/Нура, M9/Нура, M14/город. Это оптимум именно заданной учебной модели.

Подбор работает в браузере без API-ключа и без платных запросов. Вычисления разбиты на порции, чтобы показывать прогресс и позволять отмену. Найденный план появляется в предпросмотре; текущие решения меняются только по кнопке **«Применить план»**. После применения можно запросить AI-объяснение обычной кнопкой. Поиск идёт по всему применённому каталогу и районам с заданным бюджетом, текущие решения не фиксируются. При больших каталогах полный перебор может занимать длительное время; его можно отменить. Если допустимых решений нет, интерфейс сообщает об этом.

## Расчёт

Модель создаётся функцией `createModel(config)` из применённых настроек. Десять типов показателей и их веса фиксированы; районы, население, мероприятия, цены и эффекты задаёт пользователь. Встроенный `exampleConfig` в `dist/city-model.js` хранит учебный пример. Горизонт — 8 кварталов. Эффект каждой меры умножается на `(8 − lag) / 8`; общегородские меры действуют во всех районах. При включённых правилах примера синергии M1+M2, M10+M12, M5+M6 добавляются после эффектов в районе первой меры. Затем значения ограничиваются диапазоном 0–100.

`D_d = Σ_k w_k · I'_dk`; `D_avg = Σ_d pop_d · D_d`; `Score = 0.7 · D_avg + 0.3 · min(D_d) − N_crit`, где `N_crit` — число показателей строго ниже 40. Остаток бюджета не влияет на балл. Экранные объяснения строятся из рассчитанных дельт, а не генерируют новые числа. Базовое объяснение детерминированное; дополнительный AI-анализ запускается по кнопке через сервер.

Контрольные значения встроенного примера: базовый Score `52.5577` (на экране `52.56`). Набор M7/Нура, M8/Нура, M10/Нура, M12/город, M5/Сарыарка стоит 95 и даёт `56.5431` (на экране `56.54`).

## Устройство

- `dist/index.html` — структура страницы и стили.
- `dist/city-presets.js` — синтетические учебные наборы для выбора города.
- `dist/config-ui.js` — обязательная форма настройки, добавление/удаление районов и мер.
- `dist/app.js` — состояние симуляции и отображение расчёта.
- `dist/city-model.js` — общие данные, фабрика `createModel`, расчёт `compute` и валидаторы `validateConfig` / `validate` для браузера и сервера.
- `dist/optimizer.js` — полный перебор допустимых планов.
- `dist/optimizer-ui.js` — прогресс, отмена, предпросмотр и применение.
- `dist/ai-ui.js` — запрос AI-анализа, статусы и отмена устаревших ответов.
- `server.cjs` — локальный HTTP-сервер, загрузка `.env`, проверка сценария и вызов OpenAI.
- `tests/` — автоматические проверки без внешнего API.

При поддержке браузером WebMCP доступен инструмент `set_city_scenario` с общим валидатором. Ошибочный сценарий, включая неизвестный район, отклоняется до изменения состояния.
